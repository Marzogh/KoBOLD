# Recovery

If preparation fails while connected by USB, keep the reader connected. Do not
replace a partially written root update with another archive or assume an inactive
button means success. Preserve the selected backup parent and all generations.

Read-only diagnostics can inspect fixed setup records without scanning the library
backup or changing reader files. Review the expected request, phase and signed
result before repeating a device-changing action. Do not share private status,
policies, sign-in links, tokens, keys or book lists in a bug report.

## Interrupted jobs

A supported controller journals requests on native storage. On remount it resumes
the exact transaction or re-exports its committed signed result. A matching saved
nonce is required. A failed job is not a healthy receipt, even if network sync
works later. Conflicting or corrupt records must not be cleared speculatively.

## Disable or remove

Recovery actions operate only on the integration's known paths. Disabling removes
its startup marker; a normal reboot stops a currently running daemon. Removing the
startup integration preserves books, settings, payload and enrolled identity.
Unrelated services, libraries and namespaces are not removal targets.

Managed missing-file repair uses authenticated saved provenance and signed objects.
It restores absent known files only; modified files, unexpected payloads or unknown
identities stop the repair. Firmware changes require a compatibility review.

## Restore from backup

Use the manifest's actual storage generations. Later incremental reader folders
may not contain unchanged files. Restore only the necessary configuration or data;
restoring an old Kobo database can undo reading progress and annotations.

Root-overlay installation is not a complete system image or a transactional Kobo
firmware installer. A failure preventing normal boot may require factory recovery,
which can erase data. Keep off-device backups; do not promise rollback beyond the
specific tested paths and artifacts.
